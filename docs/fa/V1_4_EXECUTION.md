# وضعیت توسعه PW Agent v1.4

> **آلفا ۵:** مرکز ۲۸ ماژول LuCI با تشخیص امکانات نصب‌شده و حالت‌های واقعی؛ تغییر نام روتر، مدیریت رزرو DHCP و فعال/غیرفعال‌کردن Wi-Fi Interface با Rollback؛ بازطراحی آیکون‌های SVG، صفحه OpenVPN و ترمینال SSH انتخاب روتر. این نسخه هنوز همه افزونه‌ها و صفحات LuCI را اجرا نمی‌کند و نیازمند تست بصری و سخت‌افزاری روی روتر واقعی است.


> **آلفا ۴:** ساخت/حذف Ruleهای PBR، فعال/غیرفعال‌کردن پروفایل OpenVPN، MAC Block محدود LAN→WAN، تنظیم Queueهای SQM، تغییر کانال Wi-Fi، محافظ LAN→WAN و DNS پورت ۵۳ و کنترل RGBهای استاندارد sysfs با Rollback محلی اضافه شده‌اند. ابزار CLI ارتقای امضاشده Backend نیز موجود است. Kill Switch کامل، محدودیت سرعت هر کلاینت، SMS/Cell Lock اختصاصی و آزمون سخت‌افزاری هنوز انجام نشده‌اند.


> **آلفا ۳ (افزوده‌ها):** نصب کوتاه در ۶ خط با دکمه کپی مجزا، Safe Apply تغییر SSID با Rollback محلی ۹۰ ثانیه‌ای و بازیابی بعد از Reboot، کنترل محدود سرویس‌های DNS/DHCP/NTP، مدیریت هشدارها و زمان‌بندی‌ها و سازگاری apk/opkg.

> **قابلیت‌های Alpha 2:** کنترل روشنایی LEDهای دستی، مدیریت سرویس OpenVPN (اتصال/قطع/ری‌استارت)، ترمینال SSH تحت وب با مجوز و نمایش جدول‌بندی‌شده گزارش‌ها اضافه شده‌اند. **Ruleهای OpenVPN فقط پیش‌نمایش‌اند** و شبکه‌های حساس بدون Rollback تغییر نمی‌کنند.

## آلفا ۳ و وضعیت تحویل

- دستور نصب از یک فرمان بسیار طولانی به شش فرمان کوتاه با دکمه کپی مستقل تبدیل شده است؛ از پوشه موقت خصوصی برای دریافت فایل استفاده می‌شود.
- تغییر SSID مشخص با Snapshot و Watchdog محلی ۹۰ثانیه‌ای و دکمه تأیید از وب قابل آزمایش است؛ بعد از Reboot/Restart تغییر تأییدنشده بازیابی می‌شود.
- کنترل روشن/خاموش سرویس OpenVPN از آلفا ۲ حفظ شده، اما اعمال Ruleها همچنان **Dry Run** است.
- کنترل محدود DNS/DHCP/NTP، هشدارهای قابل ایجاد/ویرایش وضعیت، زمان‌بندی و نمایش پکیج‌های apk/opkg اضافه شده‌اند.
- **هنوز ناتمام:** تغییرات کامل WAN/Firewall، VPN Split Routing و Kill Switch، Rate Limit/Block Client، RGB/Modem اختصاصی و آپدیت خودکار cPanel. در هیچ‌کدام نباید موفقیت ساختگی اعلام شود.

## موارد پیاده‌سازی‌شده در شاخه توسعه

- حفاظت از داده‌های حساس: پاسخ‌های جزئیات روتر در API اکنون دارای Allowlist فیلدهای عمومی هستند و `secret_sealed`، توکن‌ها و Meta خام ارسال نمی‌شوند؛ تست CI برای عدم نشت این اطلاعات اضافه شده است.
- ورود مستقیم وب با نام کاربری و رمزی که در نصب تازه cPanel تنظیم می‌شود؛ رمز به‌صورت Hash، نشست HTTPS با کوکی امن، CSRF، محدودیت تلاش و RBAC. Owner می‌تواند از داخل Mini App رمز را برای نصب قبلی تنظیم یا بازنشانی کند. نشست‌های بدون اثرانگشت معتبر رمز عبور نیز به‌صورت Fail-closed رد می‌شوند و تغییر رمز، نشست‌های قبلی را باطل می‌کند.
- بازطراحی پنل مستقل با CSS اختصاصی، سایدبار حرفه‌ای، منوی بازشونده موبایل با پشتیبانی کیبورد و Escape، کارت‌های شبکه، راست‌چین/چپ‌چین، تم روشن و تیره؛ صفحه ورود دو ستونه و واکنش‌گرا با نمایش/پنهان‌سازی رمز. فونت Vazirmatn نسخه 33.0.3 از jsDelivr به همراه WOFF2 و مجوز OFL در ZIP cPanel قرار می‌گیرد؛ CDN و فونت سیستم نیز مسیر جایگزین هستند. MIME فونت و وجود فایل‌ها در CI بررسی می‌شود.
- توسعه Build برای معماری‌های بیشتر OpenWrt؛ Passwall2 برای امکانات عمومی Agent الزامی نیست. قابلیت‌ها براساس سخت‌افزار واقعی بررسی می‌شوند. خروجی `agent.capabilities` برای هر روتر وضعیت صریح `available`، `read_only`، `not_available` یا `planned` را برای Wi-Fi، Passwall2، LED، مودم، SQM، UPnP، WireGuard و OpenVPN برمی‌گرداند. نبود سخت‌افزار باید به‌صورت غیرفعال نشان داده شود، نه کنترل صوری.
- نصب روتر از **دامنه Backend روی cPanel**: فایل `install/remote.sh` در ZIP cPanel قرار می‌گیرد، بسته‌های از قبل Sync شده با درخواست POST دارای توکن Provisioning ارائه می‌شوند و روتر بعد از SHA256 و **امضای Ed25519** توکن را مصرف می‌کند. اگر فایل‌های Cache موجود نباشند، نصب‌کننده به GitHub Release بازمی‌گردد. روتر به `openssl`، `base64` و `sha256sum` نیاز دارد.
- تست اختیاری دانلود حداکثر ۲ مگابایت از Cloudflare، با فاصله حداقل ۱۰ دقیقه و هشدار افشای IP عمومی به ارائه‌دهنده تست؛ این آزمایش سرعت نهایی اینترنت و Bufferbloat نیست.
- نمایش صرفاً خواندنی تنظیمات SQM و UPnP، LEDهای sysfs و وضعیت مودم‌های ModemManager/uqmi. شناسایی پیکربندی ابزارهای DNS رمزنگاری‌شده، Adblock، DDNS، mwan3 و VLAN نیز اضافه شده است؛ رمزها یا اطلاعات خصوصی سیم‌کارت گزارش نمی‌شوند.
- افزودن تب‌های جدید LuCI و تست‌های Go، PHP، MySQL، JavaScript و امضای Installer در CI.
- تست اختیاری چراغ‌های سازگار sysfs: پس از تأیید کاربر روشنایی چراغ برای ۱٫۲ ثانیه تغییر می‌کند، سپس مقدار قبلی بازیابی می‌شود. LEDهای با Trigger فعال و نام‌های غیرمجاز رد می‌شوند؛ این عملیات هنوز کنترل کامل RGB نیست.
- ممیزی خواندنی DNS/IPv6 از وضعیت Resolver، آدرس عمومی IPv6 و مسیر پیش‌فرض، بدون ارسال IPهای DNS و بدون ادعای اثبات عدم نشت یا صحت Kill Switch.
- **انتشار مرحله‌ای Fleet با Canary:** برنامه مستقل در MySQL، نخستین موج تک‌روتری، تأیید Owner برای هر موج بعدی، بررسی وضعیت واقعی Command و Heartbeat بعد از اجرا، توقف روی خطا یا آفلاین بودن، امکان Pause/Resume/Cancel و گزارش وضعیت در پنل Web. این مکانیزم فقط برای `agent.update.check` و `agent.update.apply` مجاز است؛ لغو برنامه، فرمانی را که قبلاً صف شده بازنمی‌گرداند.

- پیش‌نمایش سیاست دستگاه بر اساس MAC با اعتبارسنجی آدرس Unicast، حالت Block/Unblock/Limit و بازه سرعت؛ هیچ قانون Firewall یا محدودکننده واقعی اجرا نمی‌شود.

## وضعیت تکمیل ۱۴ قابلیت درخواستی

|---|---|---|
| ۱ | نصب، آپدیت Backend، Migration و Rollback | نصب امضاشده، اعتبارسنجی اولیه پیش از تغییر روتر و بازیابی Agent/Init/Config در خطاهای قابل مدیریت، به‌علاوه Migration افزودنی با Ledger در MySQL اضافه شده؛ بازیابی بعد از قطع برق، LuCI و آپدیت مرحله‌ای PHP هنوز مانده است |

| ۳ | مدیریت Wi-Fi و شبکه مهمان | پیش‌نمایش نام SSID و Diff بدون تغییر تنظیمات اضافه شده؛ Safe Apply و Rollback زمان‌دار کامل نیست |

| ۵ | DNS رمزنگاری‌شده و Ad-block | عیب‌یابی و شناسایی سرویس‌های اختیاری وجود دارد؛ Adapterهای تغییر تنظیمات مانده‌اند |

| ۹ | ورود مستقل با نام کاربری و رمز | پیاده‌سازی و تست اولیه انجام شده؛ تست عملی و بازبینی امنیتی مانده |

| ۱۱ | Passwall2 و VPN | قابلیت‌های قبلی حفظ شدند؛ Native WireGuard/OpenVPN و تست مسیرهای حساس مانده |

| ۱۳ | Fleet و اعمال گروهی | Canary مرحله‌ای با تأیید Owner، توقف روی خطا و بررسی سلامت اضافه شد؛ Rollback خودکار کل Fleet و آزمون روی روترهای واقعی باقی است |

## اصل سازگاری روترها

«سازگار با مدل‌های OpenWrt» به معنای تشخیص ویژگی‌های هر روتر، نمایش صحیح وضعیت و غیرفعال‌کردن فرمان‌های ناموجود است؛ نه امکان کنترل RGB، مودم سیم‌کارتی یا Wi-Fi در دستگاهی که این سخت‌افزار و درایور را ندارد.

پیش از فعال‌کردن هر عملیات تغییردهنده WAN، Firewall، Wi-Fi، DNS یا Routing باید این زنجیره برقرار شود: **Snapshot → Diff → تأیید صریح → Apply → بررسی سلامت → Commit یا Rollback محلی با زمان‌بندی مستقل**. تا زمان تکمیل این مسیر، کنترل خطرناک در رابط فعال نشود.

## نصب و اعتبارسنجی

نسخه ۱.۴ به‌صورت Alpha و تحت برچسب GitHub Latest منتشر می‌شود؛ استفاده تنها در Staging و روتر غیرحیاتی توصیه می‌شود و نصب روی روتر اصلی بدون نسخه پشتیبان و تست Rollback مجاز نیست. بعد از انتشار امضاشده، قبل از Provisioning ابزار `openssl-util` را از مخازن سازگار Firmware نصب کن.

برای بررسی سورس، تست‌ها و بسته آزمایشی:

```sh
go test ./...
go vet ./...
python3 scripts/check_dashboard_js.py
sh scripts/test_bootstrap_signature.sh
php server/tests/web_auth_test.php
bash scripts/package_cpanel.sh
```

**نتیجه تست نرم‌افزاری به‌تنهایی تضمین عملکرد همه روترهای OpenWrt نیست.** تست قطع ارتباط و بازگشت تنظیمات روی سخت‌افزار واقعی برای انتشار پایدار ضروری است.
